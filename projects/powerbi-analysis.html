Overview

An end-to-end business intelligence solution rather than a one-off chart: a modelled dataset, a reusable measure layer, and automated publishing so the report stays current without anyone rebuilding it by hand.

The problem

Reporting built directly on a flat table works until someone asks a time-based question. Then year-to-date stops reconciling with the annual figure, filters interact in ways nobody predicted, and two people pull the same report and get different totals. At that point the report has a worse problem than being slow — nobody trusts it, so it stops being used.

The data

Transactional fact data with dimension tables for date, product and customer. The date dimension is the one that does the real work: without a dedicated, contiguous date table, time intelligence in DAX produces results that look right and are not.

Approach

  • Modelled the data as a star schema with a proper date dimension, so filter propagation is predictable instead of emergent.
  • Did the shaping in Power Query, keeping transformation logic in one documented place rather than spread across measures.
  • Wrote DAX measures including year-to-date and quarter-to-date rollups, built as reusable measures rather than repeated inline expressions.
  • Validated the data in Python before load.
  • Automated publishing to the Power BI Service.

Results

A refreshable report whose totals reconcile across time periods, with a measure layer that can be extended without rewriting the visuals that depend on it.

What I would do differently

  • The validation step is a separate Python script rather than a gate inside the refresh pipeline. That means a bad load can still publish — the check exists, but nothing enforces that it ran first. This is the change I would make before anything else.
  • The measures should be organised into display folders. With enough of them, a flat list becomes genuinely hard for anyone else to work in.
  • There is no row-level security. It was not needed here, and it would be a hard requirement before rolling this out to multiple teams with different data access.

Tech stack

Power BI with DAX and Power Query, star schema dimensional modelling, and Python for the pre-load validation.
