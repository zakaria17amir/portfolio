Overview

A command-line tool that sits in front of a coding agent. It reads the repository, has a cheap model write a short brief, lets a cheap model attempt the fix first, and escalates to an expensive one — carrying a post-mortem of the failure — only when the cheap attempt does not pass the repository's own tests. Built in a three-hour hackathon, where it took second place, and then extended with a measured benchmark rather than a claim.

The problem

You pay a coding agent the same whether the task is a typo or a refactor, and you hand it the same thin issue either way. Two wastes follow from that. The agent spends its first stretch orienting — reading files, guessing conventions, occasionally editing the wrong module — and every task gets routed to the frontier model regardless of size. preflight attacks both: brief first, size the job, spend accordingly.

The experiment

The benchmark target is a small expression calculator — tokenizer, recursive-descent parser, evaluator, unit conversion — around 300 lines across 7 files with 21 tests. Five bugs are seeded into it, sized small to large, and each is paired with an issue written the way a human writes one: symptoms only, no file names. Six arms run over those five bugs, from "just use the expensive model" to the full cascade, plus controls that isolate whether the handoff itself is doing any work.

Approach

  • Scan at zero tokens. File tree, README, test command, conventions, and files ranked against the issue's keywords — all of it computed locally, before any model is called.
  • Brief with the cheap model. Roughly a cent buys start-here files, conventions, a verification command, risks, and a size estimate that decides which tier gets the work.
  • Let the repository's own tests judge. Every attempt runs in a fresh copy under a temporary directory, and pass or fail is decided by the project's test command, not by the model's self-report.
  • Escalate with a post-mortem. A failed attempt is distilled into a structured handoff — what was tried, why it failed, the next hypothesis — rather than restarting the expensive model cold.
  • Drive CLIs, not SDKs. The agent is a subprocess, so the same cascade runs across vendors and each CLI owns its own auth. That is what made a cross-provider test possible at all.

Results

Over five bugs, one run per cell, all arms fixed 5 out of 5. The interesting difference is cost.

  • A $0.01 brief let the cheap model match the expensive one at 32% less total cost — $0.42 against $0.62.
  • The brief turned out to be portable across vendors: a brief written by one vendor's cheap model, handed to a GPT agent through a different CLI, still fixed 5 out of 5 at roughly a quarter of the cold frontier-model cost.
  • Starting cheap can lose. When the cheap tier was budget-capped, its failed attempts were empty, so the cascade paid twice and the handoff had nothing to carry — 16% more expensive than just using the strong model. That result contradicts the design, and it is the one I kept at the top of the README.

The lesson underneath it is upstream of "handoff versus clean restart": the escalation gate matters more than the handoff. Escalate on a wrong patch, not on no patch. Five bugs on a toy repository is directional, not a result, and the README says so in the same breath as the numbers.

What I would do differently

  • n = 5 bugs, one run per cell, on a 300-line repository. Agent runs are stochastic, so single runs cannot separate a real 32% saving from variance. Repeat runs per cell are the first thing to add, and until they exist every number here is a direction and not a measurement.
  • The benchmark target is one small Python project I wrote myself. The brief for a fresh clone of a real library (pallets/click, ~100 files) is included as evidence it generalises, but that is an anecdote, not an arm.
  • The dollar figures are exact for one vendor and list-price estimates for the other, which is why results are never summed across engines. A cleaner design would price everything the same way rather than labelling half of it est.
  • The escalation gate is still binary on the test result. The experiment says it should distinguish a wrong patch from no patch at all — that is the change the data actually asked for, and it is not built yet.

Tech stack

Python 3.11 with no runtime dependencies beyond pytest; agent CLIs driven as subprocesses; a static benchmark dashboard with per-model analytics and run replay, deployed on Vercel; tests and results published through GitHub Actions.
